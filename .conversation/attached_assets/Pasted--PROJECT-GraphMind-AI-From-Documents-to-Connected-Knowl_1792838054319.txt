# PROJECT: GraphMind AI — From Documents to Connected Knowledge

Act as a senior full-stack engineer, AI engineer, and premium UI/UX designer. Build a complete, functional, hackathon-ready web application called **GraphMind AI**.

The application must allow users to upload multiple PDF documents, ask questions about their contents, receive answers grounded in those documents, verify the exact source passages and page numbers, and explore relationships between concepts through an interactive knowledge graph.

This is an AI-powered document intelligence and knowledge discovery platform.

**Do not build just a static UI prototype. Build a working application with a polished frontend, functional backend, document processing, source citations, and an interactive knowledge graph.**

- Lucide React icons

- Sentence Transformers or a configured embedding API for semantic retrieval

Use persistent storage where supported by the environment.

Store document metadata, extracted text, page-level chunks, graph data, and question history.

For the hackathon MVP, SQLite is acceptable for metadata and question history. Use a suitable vector index or a reliable local retrieval implementation.

Keep the storage layer modular so that a database can be changed later.

Actions:

- Preview extracted content.
- Reprocess document.
- Delete document.

Require confirmation before deleting a document.

Deleting a document must also remove its associated chunks, graph references, embeddings, and metadata from the active knowledge base.

## PDF processing pipeline

Implement the following workflow:

1. Receive the PDF through the backend.
2. Validate that it is a readable PDF.
3. Extract text using PyMuPDF.
4. Preserve the original PDF page number for every extracted passage.
5. Split text into overlapping chunks without losing page references.
6. Store document metadata and extracted chunks.
7. Generate embeddings when a configured embedding provider is available.
8. Index the chunks for retrieval.
9. Extract important concepts and relationships.
10. Store concept-to-source references.
11. Update processing status.
12. Display the processed document in the UI.

A chunk must retain at least:
- Document ID.
- Document filename.
- Page number.
- Chunk index.
- Extracted text.
- Embedding or retrieval representation.

If a PDF is scanned and has no extractable text, clearly report that OCR is required.

Do not mark an empty-text PDF as successfully processed.

For scanned documents, implement OCR only if a suitable OCR dependency is available and can be configured reliably. Otherwise, show an informative message.

Never invent page numbers.

# 13. DOCUMENT-GROUNDED AI AND CITATION RELIABILITY

Citation reliability is a core project requirement.

Implement these safeguards:

1. Preserve PDF page numbers during extraction.
2. Preserve document IDs and filenames in each text chunk.
3. Retrieve evidence before generating an answer.
4. Pass retrieved evidence to the LLM with clear instructions not to invent unsupported information.
5. Return source references in a structured format.
6. Validate that every returned citation refers to a retrieved chunk.
7. Display only valid citations.
8. Provide a fallback when evidence is insufficient.
9. Never manufacture quotes or source passages.
10. Allow the user to inspect the original evidence.

Do not rely solely on an LLM's generated citation labels.

The application backend must control the source metadata.

When generating concept relationships, retain evidence references whenever possible.

If a relationship cannot be supported by document evidence, do not present it as a verified relationship.
